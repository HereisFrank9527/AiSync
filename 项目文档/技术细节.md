## 开发环境

必需：

- Windows 当前支持最好
- Python 3.11
- Node.js 18+

可选：

- `chromadb`：启用 Chroma 向量库后端

安装后端依赖：

```powershell
.\.conda\python.exe -m pip install -e "backend[dev]"
```

如需 Chroma：

```powershell
.\.conda\python.exe -m pip install -e "backend[vector]"
```

安装前端依赖：

```powershell
cd frontend
npm install
```

## 运行方式

开发模式：

```powershell
npm run dev
```

行为：

- 启动源码后端，默认端口 `27631`
- 启动 Vite，默认端口 `1420`
- 两者都绑定到 `0.0.0.0`，方便可信局域网设备访问
- Vite 代理 `/api` 和 WebSocket 到后端
- 开发日志写入 `.dev-logs/`

构建并启动本地 Web：

```powershell
npm run web
```

行为：

- 先构建 `frontend/dist/`
- 再启动 FastAPI
- FastAPI 同时托管前端页面、REST API 和 WebSocket
- 浏览器访问 `http://127.0.0.1:27631`

只启动已有构建产物：

```powershell
npm run web:start
```

健康检查：

```text
http://127.0.0.1:27631/health
http://127.0.0.1:27631/docs
```

## 项目库与导入导出

默认项目库由后端管理，路径来自 `PROJECTS_ROOT`，默认是：

```text
~/.aisync/projects/
```

项目库 API：

```text
GET  /api/projects
POST /api/projects
POST /api/projects/import
GET  /api/projects/export?project_path=...
```

设计决策：

- 新建项目默认进入项目库。
- 导入接受 `.zip` / `.aisync.zip`，后端会安全解压到项目库。
- 导出生成 `.aisync.zip`。
- 重命名只更新 `project.yaml` 元数据，不移动项目目录。
- 删除只允许删除项目库内项目。
- zip 导入拒绝绝对路径、空路径、`.`、`..` 和路径穿越成员。
- 导出跳过 `.vectordb`、`__pycache__` 等可重建/无关目录。

项目初始化常见目录：

```text
chapters/
```

### 人物实体与旧项目迁移

人物档案采用“结构化实体 + 自由档案”双层模型：

- `characters/{slug}/profile.yaml` 是人物实体，schema v3 起包含永久 `character_id`。
- `characters/{slug}/profile.md` 是自由人物档案，不作为跨模块引用键。
- `characters/index.yaml` 是自动维护的派生注册表，包含活跃和已归档人物；不能作为人物真源手工维护。
- 角色姓名、旧名和称号只用于解析，结构化数据应保存 `character_id`，避免改名、重名或归档后断开引用。

旧项目第一次读取人物列表时会执行兼容迁移：

- 给缺少 ID 的 YAML 补充永久 ID 和 schema 版本。
- 只有 `profile.md` 的人物会生成最小 `profile.yaml`。
- 迁移前的 YAML 原文保存到 `.aisync/migration_backups/`。
- 迁移报告保存到 `.aisync/character_migration.json`。
- 不修改人物 Markdown、章节正文、大纲 Markdown 或其他自由文本。
- 损坏 YAML、重名和模糊别名不会被强制关联，而是保留为警告或未决项。

名称解析接口：

```text
POST /api/story/characters/resolve
```

请求传入一个或多个姓名/别名，响应分为 `resolved`、`unresolved` 和 `ambiguous`。无歧义结果返回永久 `character_id`；调用方后续应保存 ID，而不是继续保存角色名字符串。

## LLM 预设

设置页支持多个 LLM 预设：

- 创建预设
- 复制已有预设
- 重命名预设
- 修改 provider / API Key / API Base / model / max tokens
- 设置请求超时秒数
- 设置上下文窗口档位
- 自动获取模型列表
- 配置主 Agent 可调用工具

支持的 provider：

- `anthropic`
- `openai`
- `custom`，用于 OpenAI 兼容 API

主要环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `LLM_PROVIDER` | `anthropic` | 默认 LLM 提供商 |
| `LLM_API_KEY` | 空 | 直接写入 API Key |
| `LLM_API_KEY_ENV` | `ANTHROPIC_API_KEY` | 从哪个环境变量读取 API Key |
| `LLM_API_BASE` | 空 | OpenAI 兼容 API 地址 |
| `LLM_MODEL_NAME` | `claude-opus-4-7` | 默认模型名 |
| `LLM_MAX_TOKENS` | `16000` | 最大输出 token |
| `LLM_ENABLE_THINKING` | `true` | Anthropic thinking |
| `LLM_EFFORT` | `high` | thinking effort |
| `LLM_PROMPT_CACHE` | `true` | Anthropic prompt cache |
| `EMBEDDING_MODEL_NAME` | 空 | 向量检索使用的 embedding 模型名 |
| `VECTOR_BACKEND` | `local` | `local` 或 `chroma` |
| `CHROMA_PERSIST_PATH` | `.vectordb/chroma` | Chroma 存储目录 |
| `PROJECTS_ROOT` | `~/.aisync/projects` | 默认项目根目录 |

## Agent 对话

Agent 对话通过 WebSocket 工作：

```text
ws://127.0.0.1:27631/api/agent/current/ws?project_path=...
```

当前能力：

- 历史对话自动加载
- 默认打开上一次对话，没有历史时才新建
- Markdown / 表格渲染
- `<think>` 思考块折叠
- 工具调用过程展示
- 任务状态和 token 估算
- 中断请求
- 对话记忆压缩
- 一致性审查默认关闭，可手动开启

中断机制：

- 前端通过 WebSocket 和独立 HTTP 请求双通道发起中断。
- 中断携带 conversation/run 信息，优先命中真实运行中的 Agent task。
- 后端会尝试 `task.cancel()`，并把持久状态收敛为 `interrupted`。
- 如果正在执行不可取消工具，可能需要等工具返回后停止后续步骤。

## 工具系统

工具通过统一描述符暴露给 Agent、工具中心和侧边栏工具页。描述符包括：

- 工具名
- 中文描述
- 输入 schema
- UI schema
- 文件读写影响
- 默认 LLM 预设
- 前端呈现方式
- 是否提供工作区页面

当前主要工具：

| 工具 | 说明 | 主要影响 |
| --- | --- | --- |
| `write_chapter` | 写入章节草稿 | 写入 `chapters/**/*.md` |
| `edit_chapter` | 编辑已有章节 | 读写 `chapters/**/*.md` |
| `create_character` | 创建角色档案 | 写入 `characters/**` |
| `character_manage` | 角色归档 | 移动到 `temp/archive/characters/**` |
| `update_worldview` | 创建或更新世界观文档 | 读写 `world/**/*.md` |
| `outline_generate` | 生成/整理大纲 | 读写 `plot/outline.*` |
| `foreshadow_manage` | 管理伏笔 | 读写 `plot/foreshadows.json` |
| `consistency_check` | 一致性检查 | 读取项目上下文，不直接写文件 |
| `search_project` | 搜索项目文件 | 读取文本文件 |

工具运行记录保存：

```text
.aisync/tool_runs/
```

工具级 LLM 路由：

- 工具中心可设置工具默认 LLM 方案。
- 当工具有独立默认 LLM 且支持 `invoke` 时，工具内部 AI 流程使用该模型。
- 没配置独立方案时保持旧行为，使用主 Agent 当前模型或直接执行工具。

## 提示词与 AGENT.md

提示词系统分层：

- AGENT.md：项目根目录单文件，保存本项目长期工作习惯和当前固定文风。
- Prompt Pack：需要跨项目复用、按阶段启用或随时切换的文风、写作、规划、润色和检查提示词。
- Workflow Step Prompt：工作流步骤级额外提示词和步骤级提示词包选择。

相关 API：

```text
GET/POST /api/prompt-packs
GET/PUT  /api/system-rules
```

设计决策：

- `AGENT.md` 每轮自动读取并追加到主 Agent 的 system prompt，但不能扩大工具权限或覆盖程序级安全边界。
- Agent 通过 `file_change_proposal` 修改 `AGENT.md`，复用现有差异确认与自动应用机制。
- 旧 `.aisync/system_rules.json` 自定义内容在缺少 `AGENT.md` 时自动迁移一次。
- Prompt Pack 用于可复用、可切换的文风和写作规则。
- 工作流步骤可以指定本步使用哪些 Prompt Pack。
- Agent run 只展示提示词来源审计摘要，不直接暴露完整 prompt 正文。

工具失败接管：

- 连续两轮工具批次全部为 `error` 或 `duplicate` 时，loop 记录 `termination_reason=human_intervention`。
- Agent 返回 `intervention` 结构，不自动重试，避免继续消耗 Token。
- 前端根据 `agent_final.metadata.intervention` 提供“重试本轮”“跳过工具并总结”“补充说明”三个动作；该 metadata 会随对话历史持久化。

只读工具预算与临时目录清理：

- `search`/`review` 类工具在项目状态未变化时最多连续成功调用 3 次；达到上限后下一轮 schema 自动隐藏只读工具，保留编辑、生成和补丁工具。
- `file_change_proposal` 的 `delete_directory` 只接受 `temp/` 下路径，服务端枚举可编辑文本文件后生成普通逐文件 delete change，仍经过 hash 校验和人工确认。
- `temp/.aisync-temp.json` 和内部隐藏路径不会进入目录清理改动包。

## 人物引用 V2

人物跨模块引用统一使用 `character_id`，不使用姓名或 slug 作为持久化键。姓名和别名只用于显示与无歧义解析。

- 章节人物关联保存在章节元数据中，不改写章节 Markdown 正文。
- 伏笔人物关联保存在 `plot/foreshadows.json`，继续与伏笔状态、章节和大纲关联共存。
- 混合格式大纲仍以 `plot/outline.md` 为正文真源；人物关联保存到 `plot/outline-meta.yaml`，按节点 ID 映射。
- 大纲结构重建后，如果节点 ID 已变化，旧关联不会猜测迁移，避免把人物错绑到新节点。
- 活跃和归档人物都可被引用；保存接口会拒绝未知 ID，前端会保留异常 ID 的可见提示而不是静默删除。
