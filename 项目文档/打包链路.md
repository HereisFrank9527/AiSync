# AiSync 打包链路

更新时间：2026-05-16

## 结论

AiSync 的开发态和安装态不是同一条运行链路：

- 开发态：运行源码前端和源码后端，主要用于快速调试。
- 安装态：运行 Tauri release exe 内嵌的前端资产，并从安装目录资源启动随包 Python 后端。

因此，前端 dev 正常不代表安装包一定包含了最新前端代码。发布前必须用 `npm run build` 完整打包，并通过发布摘要确认 release exe 内嵌的是当前 `frontend/dist` 资产。

## 命令入口

仓库根目录：

```powershell
npm run dev
```

用途：开发模式。等价于进入 Tauri dev，启动 Vite 前端和源码后端。

```powershell
npm run build
```

用途：发布模式。生成 NSIS 安装包，并自动跑发布摘要校验。

```powershell
npm run build:frontend
```

用途：只检查 TypeScript/Vite 前端构建，不生成安装包。

## 开发态链路

`npm run dev`：

1. 根目录脚本调用 `npm --prefix frontend run tauri -- dev`
2. Tauri 执行 `beforeDevCommand`
3. `scripts/tauri_dev.ps1` 检查 `http://127.0.0.1:8000/health`
4. 如后端未运行，用 `.conda/python.exe` 或系统 Python 在 `backend/` 下启动：

```powershell
python -m app.cli --host 127.0.0.1 --port 8000 --reload
```

5. 前端走 Vite dev server：`http://localhost:1420`

开发态特点：

- 前端使用源码和 Vite 热更新。
- 后端使用 `backend/` 源码。
- 默认固定 `127.0.0.1:8000`。
- 不会生成安装包，也不会证明安装包里有最新前端。

## 发布态链路

`npm run build`：

1. 根目录脚本调用 `npm --prefix frontend run tauri -- build`
2. Tauri 执行 `beforeBuildCommand`
3. `scripts/tauri_build.ps1` 执行：
   - 拷贝干净后端源码到 `frontend/src-tauri/resources/backend-src/`
   - 如缺少随包 Python，则准备 `frontend/src-tauri/resources/runtime/python/`
   - 清理旧 release 资源残留
   - 执行 `cd frontend && npm run build` 生成 `frontend/dist`
4. Tauri release 编译，把 `frontend/dist` 嵌入 `frontend/src-tauri/target/release/aisync.exe`
5. NSIS 打包生成安装包：

```text
frontend/src-tauri/target/release/bundle/nsis/AiSync_<version>_x64-setup.exe
```

6. 根目录脚本自动执行：

```powershell
npm run release:summary
```

发布态特点：

- 前端资产来自 `frontend/dist`，并嵌入 release exe。
- 后端资源来自 `frontend/src-tauri/resources/backend-src/`。
- 安装版后端优先使用 `resources/runtime/python/pythonw.exe` 或 `python.exe`。
- 安装版自动选择本地可用端口，不固定 `8000`。
- 当前发布产物收敛为 NSIS，不再把 MSI 作为主产物。

## 安装态链路

用户安装并启动 `AiSync` 后：

1. Windows 启动安装目录中的 `aisync.exe`
2. Tauri 加载 exe 内嵌前端资产
3. Rust 侧选择本地端口，并启动后端：

```powershell
runtime/python/pythonw.exe -m app.cli --host 127.0.0.1 --port <自动端口>
```

4. 前端通过 Tauri 命令读取真实 API 地址，不再假设 `8000`
5. WebSocket 连接真实后端地址

安装态诊断位置：

```text
%LOCALAPPDATA%\com.aisync.app\logs\
%APPDATA%\com.aisync.app\startup-diagnostics.txt
```

## 这次 dev/安装包不一致的原因

现象：

- 开发态修复后表现正常。
- 安装版仍显示旧行为。
- 安装版报错栈里引用旧前端资产：

```text
index-D8H8yi5d.js
```

排查结果：

- 当前 `frontend/dist/index.html` 指向的新资产不是旧文件。
- 旧 `0.1.7` release exe 内嵌的是 `assets/index-D8H8yi5d.js`。
- 因此安装版不是在运行当前源码构建，而是在运行旧安装包/旧 release exe。

完整原因链：

1. 开发时修的是源码和 Vite dev server，dev 立即可见。
2. 当时只确认了前端构建或旧安装包，没有确认 release exe 是否重新嵌入最新 `frontend/dist`。
3. 旧 `0.1.7` 安装版仍然留在本机，窗口标题也是 `AiSync 0.1.7`。
4. 同版本覆盖安装容易误判：Windows/NSIS 可能进入维护/覆盖逻辑，不能可靠证明已替换为新 exe。
5. 旧 exe 中仍含旧前端资产 `index-D8H8yi5d.js`，所以安装态继续表现为旧 UI/旧 bug。

关键教训：

- 只跑 `npm run build:frontend` 或 `cd frontend && npm run build` 只会更新 `frontend/dist`，不会更新安装包。
- 同版本覆盖安装不可靠。`0.1.7` 覆盖 `0.1.7` 可能让人误以为已更新，但实际仍在跑旧 exe。
- 每次发安装包必须递增 `frontend/src-tauri/tauri.conf.json` 里的版本号。
- 发布链路必须检查“当前 dist 资产是否嵌入 release exe”，不能只看安装包文件存在。

## 当前防线

已加入发布摘要校验：

```powershell
npm run release:summary
```

它会检查：

- release exe 是否存在
- NSIS 安装包是否存在
- 随包 Python 是否存在
- 后端源码资源是否存在
- `frontend/dist/index.html` 引用的 JS/CSS 资产是否真的嵌入 release exe

如果 release exe 没有当前前端资产，会直接失败，避免继续安装旧包。

根目录 `npm run build` 已经串联：

```text
tauri build -> release_summary
```

因此只要发布摘要失败，就不应该安装或发布该安装包。

## 发布前检查清单

1. 修改版本号：

```text
frontend/src-tauri/tauri.conf.json
```

2. 根目录执行：

```powershell
npm run build
```

3. 确认摘要中：

```text
EmbeddedInReleaseExe : True
```

4. 安装新生成的 NSIS：

```text
frontend/src-tauri/target/release/bundle/nsis/AiSync_<version>_x64-setup.exe
```

5. 启动后确认窗口标题版本号等于新版本。

## 常见误区

- `npm run build:frontend` 不是发布打包。
- `cd frontend && npm run build` 不是发布打包。
- `frontend/dist` 新，不代表已安装程序新。
- 同版本安装包不适合验证升级。
- dev 连接 `8000`，安装版使用自动端口，两者后端链路也不同。

## 快速清理

默认安全清理：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/clean_build_artifacts.ps1
```

先预览不删除：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/clean_build_artifacts.ps1 -DryRun
```

默认会清理：

- `frontend/dist/`
- `.dev-logs/`
- `.runtime-cache/`
- 根目录临时 `*.log`
- `frontend/src-tauri/target/release/wix/`
- `frontend/src-tauri/target/release/bundle/msi/`
- 旧版 NSIS 安装包

默认会保留：

- 最新 NSIS 安装包
- `frontend/src-tauri/resources/runtime/`
- `frontend/src-tauri/resources/backend-src/`
- `frontend/src-tauri/target/` 下的 Rust 编译缓存
- `node_modules/`
- `.conda/`

清掉所有安装包：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/clean_build_artifacts.ps1 -AllInstallers
```

需要重新完整打包时，可先运行默认清理，再执行：

```powershell
npm run build
```

## 文件清理建议

通常可以直接删：

- 旧版本 `frontend/src-tauri/target/release/bundle/nsis/AiSync_*.exe`
- 全部 `frontend/src-tauri/target/release/bundle/msi/`
- `frontend/src-tauri/target/release/wix/`
- `frontend/dist/`
- `.dev-logs/`
- `.runtime-cache/`
- 根目录测试日志 `*.log`

谨慎删除：

- `frontend/src-tauri/resources/runtime/`：删了会导致下次打包重新准备随包 Python，可能要联网或耗时。
- `frontend/src-tauri/resources/backend-src/`：删了没关系，下次发布打包会重新复制，但当前安装包摘要可能无法通过。
- `frontend/src-tauri/target/`：可释放大量空间，但下次 Rust/Tauri 编译会明显变慢。
- `frontend/node_modules/`：可释放空间，但下次需要重新 `npm install`。
- `.conda/`：开发后端依赖环境，删了要重建。

不应清理：

- 用户项目目录。
- `%APPDATA%\com.aisync.app` 中的配置和会话数据，除非明确要重置应用状态。
- `.git/`。
- 源码目录 `backend/`、`frontend/src/`、`frontend/src-tauri/src/`。
