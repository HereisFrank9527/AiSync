# AiSync Web 运行链路

更新时间：2026-08-01

## 结论

AiSync 当前主线已经切换为本地 Web / 局域网 Web：

- 开发态：FastAPI 后端 + Vite 前端，Vite 代理 `/api` 和 WebSocket。
- 构建态：只生成 `frontend/dist/` 静态资源。
- Web 运行态：FastAPI 托管 `frontend/dist/`，浏览器访问同一个后端端口。
- 不再维护 Tauri、NSIS、MSI、随包 Python runtime 和桌面安装包链路。

这意味着以后判断“是不是最新程序”，主要看当前源码、`frontend/dist/` 和正在运行的后端进程，而不是检查安装目录里的 exe。

## 命令入口

仓库根目录：

```powershell
npm run dev
```

用途：开发模式。当前等价于 `npm run dev:lan`，同时启动源码后端和 Vite 前端。

```powershell
npm run build
```

用途：构建前端静态资源。产物是 `frontend/dist/`，不生成安装包。

```powershell
npm run web
```

用途：构建前端后启动 FastAPI，由后端托管 Web 页面和 API。

```powershell
npm run web:start
```

用途：直接启动 FastAPI 托管已有 `frontend/dist/`。

```powershell
npm run release:check
```

用途：检查根目录、前端、后端版本一致，且旧 Tauri 路径和 PyInstaller 依赖没有回流。

```powershell
npm run release:web
```

用途：构建前端并生成面向使用者的 Web ZIP。开发者构建时需要 npm，ZIP 使用者不需要 npm。

## 开发态链路

`npm run dev`：

1. 根目录脚本调用 `scripts/dev_lan.ps1`。
2. 脚本检查并启动后端：

```powershell
python -m app.cli --host 0.0.0.0 --port 27631 --reload
```

3. 脚本启动 Vite：

```powershell
npm --prefix frontend run dev -- --host 0.0.0.0
```

4. 浏览器访问：

```text
http://127.0.0.1:1420
http://局域网IP:1420
```

开发态特点：

- 前端使用 Vite 热更新。
- 后端使用 `backend/` 源码。
- Vite 负责把 `/api` 和 WebSocket 代理到 `127.0.0.1:27631`。
- 当前 LAN dev 没有登录/鉴权，只适合可信局域网。

## Web 运行态链路

`npm run web`：

1. 执行 `npm run build` 生成 `frontend/dist/`。
2. 执行 `scripts/web_start.ps1`。
3. FastAPI 启动在 `127.0.0.1:27631`。
4. FastAPI 托管 `frontend/dist/`，同时提供 `/api` 和 WebSocket。
5. 浏览器访问：

```text
http://127.0.0.1:27631
```

Web 运行态特点：

- 前端和 API 同源，减少跨端口问题。
- 不需要桌面壳。
- 不需要安装器。
- 适合本机使用、局域网演示、后续部署到内网服务器。

## 发布建议

当前发布不再上传桌面安装包。GitHub Release 至少包含：

- tag，例如 `v0.2.0`
- 主要变更说明
- 已知问题
- `AiSync-web-v0.2.0.zip`
- `AiSync-web-v0.2.0.zip.sha256`

发布 ZIP 的运行链路：

1. 使用者解压 ZIP，不需要 Node.js 或 npm。
2. `start.ps1` 首次运行时调用 `setup.ps1`。
3. `setup.ps1` 检查 Python 3.11，创建包内 `.venv` 并通过 pip 安装后端依赖。
4. `start.ps1` 从包内后端源码启动 FastAPI。
5. FastAPI 托管包内 `frontend/dist/`，浏览器访问 `http://127.0.0.1:27631`。

当前发布包仍要求系统具有 Python 3.11，且首次安装依赖需要联网。它解决的是“使用者不应安装 npm”，不是完全免运行时分发。

推送 `v*` tag 后，`.github/workflows/release-web.yml` 会在干净的 GitHub Runner 上重新安装依赖、运行后端测试、构建发布 ZIP 并上传 Release。这样发布资产不依赖开发机残留的 `frontend/dist/`。

前端检查更新仍读取：

```text
https://api.github.com/repos/HereisFrank9527/AiSync/releases/latest
```

如果 Release 里有 `.zip` 或 `.tar.gz` 资产，前端会优先给出下载入口；否则退回打开发布页。

## 快速清理

默认安全清理：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/clean_build_artifacts.ps1
```

先预览不删除：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/clean_build_artifacts.ps1 -DryRun
```

默认会清理：

- `frontend/dist/`
- `.dev-logs/`
- `.runtime-cache/`
- 仓库根目录临时 `*.log`

通常不要删除：

- `backend/`
- `frontend/src/`
- `frontend/node_modules/`，除非准备重新安装依赖
- `.conda/`，除非准备重建 Python 环境
- 用户项目目录与项目内 `.aisync/`

## 旧安装包问题如何看待

旧 Tauri/安装包阶段出现过“dev 正常但安装包不是最新”的问题，根因是安装包内嵌了旧 `frontend/dist` 资产。Web-only 后这个问题不再属于主链路：

- 开发态看 Vite 当前源码。
- Web 运行态看当前 `frontend/dist/`。
- 重新构建只需要跑 `npm run build`。
- 重新启动只需要停止旧后端进程并重新运行 `npm run web:start` 或 `npm run dev`。
