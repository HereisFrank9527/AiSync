# Agent 能力说明

更新时间：2026-07-29

本文记录 AiSync 当前主 Agent 已具备的实际能力，供后续开发、测试和使用说明参考。

## 一、对话与运行

- 支持项目内多轮对话，历史记录存储在项目 `.aisync/conversations/` 下。
- 启动时优先恢复上次激活对话；没有历史时才新建对话。
- 支持流式回复，前端实时渲染 Markdown、表格、代码块、任务列表和引用。
- 支持中断当前回复；中断后会收敛运行状态，避免旧会话长期显示等待响应。
- 每轮对话会生成 Agent run 记录，存储在 `.aisync/agent_runs/` 下。
- 前端 Agent 任务区显示当前运行阶段、run_id、输入摘要、失败原因和工具调用摘要。
- 失败后提供复制错误、重试本轮、带错误继续问等恢复入口。

## 二、记忆能力

- 当前 conversation 的近期消息会随请求注入模型。
- 超出近期窗口的旧消息会压缩为会话摘要，并在后续请求中注入。
- 摘要更新在后台执行，不阻塞当前回复。
- 前端可显示记忆状态：近期窗口、总消息数、旧消息数、摘要长度、更新时间和质量评分。
- 摘要质量检查覆盖小说设定、用户偏好、未完成事项和空摘要失败场景。

## 三、工具调用能力

- 主 Agent 可调用注册在后端 `app.tools` 下的工具。
- 工具由 Tool Descriptor 描述能力、参数 schema、文件读写范围、结果呈现类型和工作区入口。
- 对话里可选择本轮 Agent 可调用工具；默认全部工具可调用。
- 设置页可配置主 Agent 默认可调用工具集合。
- 工具调用事件会前台显示工具名、参数摘要、执行耗时和错误。
- 工具运行记录持久化到 `.aisync/tool_runs/`，工具中心可查看历史、复用参数。
- `read_project_files` 支持先用 `inspect` 查看文件总行数、字符数和 Markdown 标题行，再通过 `selections` 指定起止行读取局部；模型可以自行选择相关行段，整体重写时仍可读取全文。

## 四、项目对象能力

Agent 及相关工具当前可读写和辅助管理以下小说对象：

- 基础信息：小说名、状态、简介、创作目标、目标章节数、目标字数。
- 大纲：读取 `plot/outline.md` / `plot/outline.json`，支持生成、续写、节点编辑、状态、排序和章节关联。
- 章节：读取和保存 `chapters/**/*.md`，支持章节状态、摘要、目标字数、修订轮次和大纲节点关联；正文写作可以直接在 Agent 对话中提出，由 Agent 调用 `write_chapter` 写入正式章节，也可以在工作流里先生成 `temp/drafts` 草稿。
- 长章节：预计正文超过约 6000 字符时，Agent 会使用内部 `chapter_draft` 缓冲，依次建立草稿、按顺序追加不超过 5000 字符的正文分块，最后只用草稿 ID、伏笔和事实生成统一差异包；不再把整章塞进一次工具 JSON。
- 章节长期事实：写章、改章和章节工作流可在原本那次模型输出中同时声明本章结束后的身份、状态、关系、位置、持有物、时间点和世界规则，按章节保存到 `plot/facts/**/*.json`；单章最多 12 条，不额外调用一次模型。
- 角色：读取 `characters/**/profile.yaml` 与 `profile.md`，支持创建角色档案。
- 世界观：读取和保存 `world/**/*.md`，支持通过工具新增、追加或重写设定文档。
- 伏笔：读取和保存 `plot/foreshadows.json`，记录状态、重要性、埋设章节、回收章节、关联大纲、相关文件、标签和备注。
- 写作相关请求会自动压缩注入相关伏笔上下文，优先匹配章节路径、章节元数据中的大纲节点、相关文件、标签和标题关键词，并附带命中原因与建议动作。

## 五、向量与一致性

- 支持项目级本地向量/混合索引，覆盖章节、角色、世界观和剧情相关文件。
- `plot/facts/**/*.json` 会自动进入现有项目索引，后续检索和一致性审查可以优先利用短小、结构化的章节事实，而不必每次先从整章正文里重新猜取状态。
- 可手动重建索引，前端显示索引状态、文件数、片段数和分组分布。
- 写章节工作区可检索当前章节相关设定。
- 主 Agent 请求前会自动检索相关项目上下文并注入。
- 一致性检查默认关闭，开启后才会调用；可为 `consistency_check` 单独选择便宜 LLM 预设，未单独配置时复用主 Agent 当前模型。
- 一致性检查先用精确实体词与现有语义索引混合召回候选。角色姓名位于 Markdown 标题或 YAML `name/姓名` 字段时会获得额外权重，长档案不会再仅因片段归一化而漏检。
- 保守规则只提示同一对象、同一属性、同一时间范围内的明确冲突，目前覆盖年龄、比例、人口、距离、时长、年份、等级、容量、温度、速度及生死/存在/损毁状态；普通高相关内容、不同对象数字、章节编号和时间推进不算冲突。
- 阿拉伯数字与常见中文数字会统一比较，例如 `20岁` 与 `二十岁` 相同；标题中的角色名可下传为后续结构化字段的对象锚点。
- LLM 复核可确认规则提示或返回无冲突；合法空结果不会被规则强行覆盖，只有模型输出无法解析时才明确标记为规则降级。
- 审查 LLM 的 Token 会计入 Agent 运行统计；单次最多使用 12 个候选片段、2000 个输出 Token，完整问题列表留在前端，回传主模型的结果会压缩为前三条摘要。
- 一致性结果卡会显示审查模式、实际模型、供应商、工具预设、输入/输出/总 Token、候选片段和审查文件；文件范围默认折叠。
- 每条冲突支持并列展示“新内容”和“已有设定”短证据，并使用“明确冲突 / 可能冲突 / 建议复核”中文级别；模型格式异常时会明确显示规则降级。
- 一致性结果及其审查元数据会保存到对话历史，刷新后仍可查看；普通项目检索结果继续只保留在本轮实时界面，避免历史记录膨胀。
- 章节事实快照属于派生索引，记录正文证据、确定性和来源章节；章节正文仍是最终证据。编辑章节时不传 `fact_records` 会保留旧快照，显式传空数组才会清空该章事实。

## 六、前端交互能力

- Agent 回复支持 Markdown 渲染和工具结果 AI 渲染。
- 支持消息选择、复制、引用；引用以输入框上方摘要形式存在，不污染输入正文。
- Agent 需要用户决策时会调用内部 `present_choices` 协议工具；普通 Markdown 列表不会再被猜测为选择控件。
- 结构化选择支持单选、多选、多个独立选择组、必选/可选和最少/最多数量限制；多个组统一提交，提交后历史记录会恢复并锁定已选项。
- 选择结果同时保存为可读消息和结构化元数据，下一轮 Agent 可准确读取组与选项，不依赖“我选择了第几个”这类模糊文本。
- Agent 任务区动态展示检索上下文、请求模型、执行工具、整理回复、完成/失败等阶段。

## 七、当前边界

- LLM 仍依赖外部 API，不包含本地大模型。
- 工具取消目前主要是运行状态收敛和后续步骤阻止，不保证能强杀所有长任务。
- Agent 对项目文件的理解依赖当前工具、向量索引和会话记忆，不等同于全量实时解析整个项目。
- 分段阅读由模型根据文件标题和行数选择范围，适合局部核对与修改；涉及全局结构、跨段引用或整体重写时仍需读取更多范围或全文，不能机械地永远只读局部。
- 章节事实目前由写章模型声明并由用户随正文差异一起确认，没有额外模型复核；它用于缩小后续一致性候选范围，不应覆盖与正文冲突的内容。
- 工作流分段写作暂列为备用方案，不作为当前正文写作主入口；只有长章节输出不稳定、需要多模型分工或必须逐段人工确认时再启用，日常写章优先使用直接对话和章节工具。
- 伏笔管理已接入章节页提醒和写作上下文注入；章节页和 Agent 上下文都会展示命中原因与建议动作。后续可继续增强回收风险评估和自动状态流转。
- 世界观文档重命名/删除、角色重复检查、人物关系图和导出功能尚未完成。

## 八、工具调用稳定性与诊断
- 普通对话仍会正常注入会话记忆、向量上下文、伏笔上下文、提示词包和可用工具列表，不再因为短输入自动跳过上下文。
- Agent run 的 `prompt_audit.usage.llm_calls` 会记录每次模型请求的阶段、轮次、供应商、模型、是否流式、消息数、工具 schema 数、是否包含工具结果、估算输入 token、完成状态和错误类别。
- 工具调用后的模型续轮标记为 `tool_finalize`：该轮默认不再携带工具 schema，并关闭流式请求，降低 OpenAI 兼容接口在 `assistant.tool_calls + tool_result` 续轮上的超时或参数兼容问题。
- 前端 Agent 任务报告会显示最后一次模型请求摘要，用来区分“首轮模型未返回”和“工具执行后整理回复未返回”。
- `search_project` 和 `consistency_check` 的完整结果保留在 `ui_hint` 供前端渲染；回传给模型的 `content` 只保留命中数量和前几条摘要，减少工具续轮 token 压力。
- Prompt 组装采用缓存友好顺序：system prompt 在最前，长期 Prompt Pack 排在动态会话摘要、近期历史、向量上下文和当前请求之前；发送的信息基本不减少，只调整稳定内容的位置。
- Anthropic 预设开启 prompt cache 时，system prompt 和工具 schema 会附加 ephemeral cache 标记；OpenAI 兼容接口继续依赖供应商自身的自动缓存机制。
- 工具调用后已从固定安全收尾升级为受控续轮：续轮继续允许工具调用，但关闭流式、使用瘦续轮上下文，并保留最大迭代上限。
- 长章节分块属于受控工具续轮，默认最大迭代次数提高到 12；开始和追加阶段只在 Agent 状态中显示累计字符数，不把每个内部草稿结果铺进聊天区，最终差异包仍正常显示和等待确认。
- `write_chapter` 的模型工具 schema 将单次正文限制为 6000 字符；达到输出上限时不会执行残缺 JSON，并会提示改用 `chapter_draft`。草稿分块使用严格 sequence，重复、跳号和超过 5000 字符都会拒绝。
- 续轮上下文保留长期提示词、会话摘要、少量近期历史、原始用户请求和工具链结果摘要；不重复携带首轮向量检索全文，模型需要更多资料时应继续调用检索工具。
- 如果工具续轮出现超时、参数错误或通用模型错误，会自动降级为 `tool_finalize` 安全收尾，不再继续暴露工具 schema。
- 如果连续两轮工具批次都失败或重复，Agent 不再把本轮标记为 failed，而是返回结构化人工接管选项：重试本轮、跳过工具并总结、补充说明。选项会随 `agent_final.metadata.intervention` 写入对话历史，刷新后仍可操作。
- 普通创作决策与工具失败接管是两套独立协议：`present_choices` 负责模型主动发起的单选/多选问题，`intervention` 只处理工具停滞后的恢复动作。
- 只读搜索/审查工具增加结构化预算：项目状态未发生变化时连续成功检索 3 次后，下一轮不再暴露只读工具，但仍保留写入/补丁工具，避免 Agent 无限检索不执行。
- `file_change_proposal` 支持仅限 `temp/` 的 `delete_directory`，后端会将目录展开成逐文件删除差异；`temp/.aisync-temp.json` 等内部保留文件不会被清理。

## 模型思考强度

- LLM 预设中的“思考强度”控制支持推理的模型投入的推理预算，独立于输出最大 Token 和上下文窗口。
- Anthropic 使用 `output_config.effort`；DeepSeek 使用 `thinking` 加 `reasoning_effort`，低、中、高会保持原级别，超高和最高安全映射为高。
- OpenAI 或兼容接口只对模型名明确属于 `o1/o3/o4/gpt-5/reasoner` 的模型发送 `reasoning_effort`；普通模型不发送未知参数，避免兼容中转站返回 400。
- 关闭“启用思考模式”后不会发送思考强度；部分模型或中转站不支持强度控制时会忽略该设置或返回供应商错误，应按模型文档选择。

## 联网搜索

- LLM 预设支持“启用联网搜索”，默认关闭。开启后主 Agent 会获得显式 `web_search` 工具，不再给每次普通对话偷偷附加联网参数。
- Agent 只有在明确调用 `web_search` 时才搜索。联网策略可选自动、Tavily 优先、仅 Bing RSS 或仅供应商原生；自动模式按 `Tavily -> Bing RSS -> 模型原生` 降级。
- Tavily 使用官方 Search API Bearer 鉴权，返回相关正文片段、标题和 URL；单次最多可配置 20 条来源，默认 5 条。`basic` 每次约 1 credit，`advanced` 每次约 2 credits；Advanced 会请求每个来源最多 3 个相关片段。
- Tavily 可选请求清洗后的网页正文，单个来源最多注入约 4000 字符；默认关闭，以控制延迟和 Agent 工具续轮上下文。
- 未配置 Tavily Key 时自动模式直接使用 Bing RSS；Tavily 请求失败不会泄露 Key，会继续降级到免费搜索和供应商原生搜索。
- `web_search` 可以在工具设置中单独选择 LLM 预设；独立公开搜索成功时不会使用该模型，只有回退供应商原生搜索时才使用工具预设或当前主 Agent 的 LLM。
- 搜索请求只携带查询文本和专用短提示，不注入项目向量上下文、完整对话历史或项目工具列表；结果作为普通工具结果回到 Agent loop，Agent 可继续使用其他工具。
- AiSync 会解析 Anthropic 的网页搜索结果/引用块、OpenAI 的 URL citation，以及兼容中转站常见的 `citations`、`sources`、`references`、`search_results` 等来源字段，并在搜索结果卡和最终回复下显示来源。
- 来源会随 `agent_final.metadata.web_sources` 写入对话历史；跨工具轮次最多保留 12 个去重后的 HTTP/HTTPS 来源，刷新对话后仍可查看。
- 搜索内部 LLM 的实际 Token 会并入 Agent run 总统计，并在 `tool_llm_calls` 中单独保留工具名和用量。
- Tavily 返回的 `usage.credits` 会计入 Agent run 的 `search_credits` 和 `search_calls`；前端任务摘要显示本轮联网额度，便于观察付费消耗。
- 搜索子请求会明确要求供应商在正文末尾列出实际检索到的完整 HTTP/HTTPS 地址。结构化引用缺失时，AiSync 可降级接收响应正文中明确返回的来源链接；没有任何来源地址时仍会失败，不会根据标题或模型陈述猜测、补造 URL。
- `web_search` 查询公开互联网；`search_project` 只检索当前小说项目，两者是不同工具。

## 九、文件改动确认闭环

- Agent 现在可以调用 `file_change_proposal` 提出跨文件改动包，用于清理旧设定、改写角色档案、整理大纲等需要多文件协同的任务。
- `read_project_files` 可按明确路径一次读取最多 12 个项目文本文件；跨文件修改应先读取完整目标内容，不再只依赖向量检索片段拼接新文件。
- `file_change_proposal` 不直接写入正式文件，只在 `.aisync/change_sets/` 保存待确认改动、旧内容 hash、diff 和改动原因。
- 修改已有文件时可使用 `replace_text`、`append_text`、`prepend_text`：分别用于精确替换、末尾追加和开头前置；新建文件或整体重写才使用完整 `write`。
- `replace_text` 的旧文本必须在当前文件状态中恰好出现一次，零匹配或多匹配都会拒绝整个提案；将 `new_text` 设为空字符串可精确删除唯一匹配段落。
- 同一文件的多个局部操作按提交顺序执行，并在差异卡中合并成一项最终文件改动；局部操作不能与该文件的完整写入或删除混用。
- 前端会把 `changeset:proposal` 渲染为可折叠差异预览；Agent 暂停等待用户选择“应用全部”“丢弃”或“稍后处理”，之后在同一轮继续验证或收尾。
- 同一模型轮次提交的多个 `file_change_proposal` 会合并成一个改动包；如果同轮并列调用多个不同写入工具，后端会阻止整批写入并要求汇总，避免部分文件先成功。
- 应用时后端会重新校验目标文件 hash；如果文件在 proposal 生成后被改过，会拒绝覆盖，避免过期改动误写。
- 局部操作只负责生成最终候选内容；改动包仍保存最终完整内容和旧 hash，因此沿用相同的差异预览、冲突检查、一次确认与应用后核验链路。
- 应用成功后会逐文件核验实际内容或删除结果；本轮随即收敛为只读验证阶段，不再生成第二个写入确认。核验结果显示在差异卡和 Agent 运行报告中。
- 当前版本支持 `.md/.txt/.json/.yaml/.yml/.csv` 文本文件，屏蔽 `.aisync`、`.vectordb`、点号内部路径和 `temp/.aisync-temp.json`。
- 这套能力用于替代“Agent 说自己只能搜索、然后让用户复制粘贴”的低效流程；保留人工确认，但把确认集中到最终 diff，而不是每一步工具调用都打断。
- 主 Agent 系统提示词已明确要求：正式文件改写无法由专用工具覆盖时，应使用 `file_change_proposal`，不得把问题推回给用户手动粘贴。
- 为兼容旧前端或旧预设保存的工具名单，后端会在“旧全工具名单只缺 `file_change_proposal` 和可选一致性审查工具”时自动补入改动提案工具；前端工具列表刷新时也会把它并入编辑类工具集合。

### 项目自律文件 AGENT.md

- 项目根目录 `AGENT.md` 是当前项目长期工作习惯和固定文风的唯一生效文件，每轮 Agent 对话自动读取。
- 用户要求长期记住偏好、调整项目文风或修改工作习惯时，Agent 可通过 `file_change_proposal` 提议更新；同类问题被反复纠正并可确认是长期偏好时，也可主动提出更新。
- 默认仍展示差异并等待用户确认；对话区开启“自动应用改动”后可直接写入。
- `AGENT.md` 不保存人物、伏笔、世界观、大纲等项目事实或单次任务，也不能改变工具权限、安全边界和程序级规则。
- 需要跨项目复用、按阶段启用或随时切换的文风继续由 Prompt Pack 管理。
