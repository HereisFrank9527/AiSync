## 每次发布前需要做

1. 运行 `npm run build`。
2. 运行必要的后端检查或测试。
3. 到 GitHub 创建 Release，tag 建议使用 `v版本号`，例如 `v0.2.0`。
4. Release 正文写清变更、已知问题和启动方式。
5. 如有分发包，上传 `.zip` 或 `.tar.gz`。
6. 发布后打开应用设置页，点击“检查更新”验证能看到新版本。

## 后续可选升级方向

1. 提供 Web runtime zip：包含后端源码、前端 dist、一键启动脚本和依赖安装说明。
2. 提供 Docker / compose 部署方式，方便内网服务器长期运行。
3. 增加 GitHub Actions 自动构建前端并打包 release zip。
4. 增加应用内“下载并解压更新包”的能力，但需要先设计权限、备份和回滚。

## 注意

- GitHub Releases 的 tag 要能和应用版本对应，推荐 `v0.2.0` 这种格式。
- 当前检查更新依赖访问 GitHub；离线环境会显示请求失败。
- 自动替换本地源码或运行目录风险较高，暂不作为当前主线。
