# AiSync Web 发布流程

更新时间：2026-08-01

本文档用于 Web-only 阶段的发布核对。当前不再生成桌面安装包。

## 1. 发布前检查

- [ ] 确认工作区没有误提交的大文件：`node_modules/`、`.conda/`、`.runtime-cache/`、日志、项目数据。
- [ ] 确认 README 和 `项目文档/技术细节.md` 的启动方式仍准确。
- [ ] 运行 `npm run release:check`，确认根目录、前端和后端版本一致。
- [ ] 确认 GitHub Release tag 与仓库版本一致，例如仓库 `0.2.0` 对应 `v0.2.0`。
- [ ] 确认发布说明写清用户可见变化、已知问题和启动方式。

## 2. 本机构建

```powershell
npm run release:web
```

构建产物：

```text
.release/AiSync-web-v0.2.0.zip
.release/AiSync-web-v0.2.0.zip.sha256
```

`release:web` 会先执行版本检查和前端生产构建，再复制最小后端源码、前端静态资源、启动脚本、许可证和变更记录。发布 ZIP 不包含 npm、`node_modules`、测试、日志、项目数据或本机配置。

解压后验证发布包：

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

访问：

```text
http://127.0.0.1:27631
```

## 3. 回归检查

- [ ] `http://127.0.0.1:27631/health` 返回正常。
- [ ] 首页可加载。
- [ ] 可选择或新建项目。
- [ ] Agent WebSocket 可连接。
- [ ] 设置页 LLM 预设可读取。
- [ ] 文件树、章节、世界观、工作流至少各打开一次。
- [ ] `npm run build` 无 TypeScript/Vite 错误。
- [ ] ZIP 解压后不存在 `node_modules/`、`.conda/`、缓存、日志和用户项目。
- [ ] ZIP 中存在 `backend/app/`、`frontend/dist/index.html`、`setup.ps1`、`start.ps1`、`LICENSE` 和 `VERSION`。
- [ ] 没有安装 npm 的测试环境可以运行发布 ZIP；首次启动只要求 Python 3.11。

可选后端检查：

```powershell
.\.conda\python.exe -m compileall backend\app
.\.conda\python.exe -m pytest backend\tests
```

## 4. GitHub Release

1. 提交并推送通过验收的发布快照。
2. 创建并推送与版本一致的 tag，例如 `v0.2.0`。
3. 正文写清：
   - 主要变化
   - 破坏性变化
   - 启动命令
   - 已知问题
4. `.github/workflows/release-web.yml` 会重新执行测试和构建，并创建或更新 GitHub Release。
5. Release 应包含 `AiSync-web-vX.Y.Z.zip` 和对应 `.sha256` 文件。
6. 发布后在 AiSync 设置页点击“检查更新”，确认能看到最新 release。

## 5. 更新检查验收

- [ ] 设置页能显示当前版本、最新版本、发布时间。
- [ ] 同号或低版本不会提示发现新版本。
- [ ] 有 `.zip` / `.tar.gz` 资产时显示下载入口。
- [ ] 无可下载资产时仍可打开发布页。
- [ ] 网络失败、GitHub API 失败、打开链接失败时前台显示错误。

## 6. 发布后记录

- [ ] 更新 `项目.md`。
- [ ] 更新 `规划..md`。
- [ ] 如建立了 `CHANGELOG.md`，同步写入变更。
- [ ] 如发现启动或 Agent 问题，把复现步骤和日志位置写入项目记录。
