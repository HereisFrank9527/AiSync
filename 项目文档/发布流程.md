# AiSync 发布流程

本文档用于每次发布前后核对，避免“能打包但客户机不能启动”或“检查更新找不到安装包”。

## 1. 发布前检查

- [ ] 确认工作区没有误提交的大文件：`target/`、`node_modules/`、`runtime/`、日志、项目数据。
- [ ] 确认 `frontend/src-tauri/tauri.conf.json` 的 `version` 已递增。
- [ ] 确认 README 和 `技术细节.md` 中的版本/打包说明没有过期。
- [ ] 确认 GitHub Release tag 使用 `v版本号` 或纯版本号，例如 `v0.1.7`。
- [ ] 确认发布说明写清楚用户可见变化、已知问题和升级注意事项。

## 2. 本机构建

```powershell
cd frontend
npm run build
cargo check --manifest-path src-tauri/Cargo.toml
npm run tauri build
```

构建产物：

```text
frontend/src-tauri/target/release/bundle/nsis/AiSync_<version>_x64-setup.exe
frontend/src-tauri/target/release/bundle/msi/AiSync_<version>_x64_en-US.msi
```

当前优先发布 NSIS 安装包：`AiSync_<version>_x64-setup.exe`。

生成发布摘要：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/release_summary.ps1
```

摘要会检查版本号、NSIS/MSI 产物、随包 Python runtime 和后端源码资源是否存在，并输出安装包哈希。

## 3. 安装包回归

覆盖安装：

- [ ] 用新 NSIS 安装包覆盖当前已安装版本。
- [ ] 确认 `%LOCALAPPDATA%\AiSync\aisync.exe` 时间戳/哈希已变化。
- [ ] 确认注册表卸载项版本已更新。

启动检查：

- [ ] 启动 `%LOCALAPPDATA%\AiSync\aisync.exe`。
- [ ] 设置页或启动诊断显示当前版本正确。
- [ ] `startup-diagnostics.txt` 中 `backend_health=true`。
- [ ] `resource_dir` 指向 `%LOCALAPPDATA%\AiSync`，不是源码目录或 `target/debug`。
- [ ] 后端使用随包 `runtime\python\pythonw.exe`。
- [ ] 关闭主窗口后，安装目录下没有残留 `aisync.exe` / `pythonw.exe`。

可用脚本做已安装版本冒烟检查：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/smoke_installed_app.ps1
```

该脚本会启动已安装的 AiSync、读取启动诊断、确认 `backend_health=true`，再关闭窗口并检查安装目录下是否残留托管进程。

诊断路径：

```text
%APPDATA%\com.aisync.app\startup-diagnostics.txt
%LOCALAPPDATA%\com.aisync.app\logs\
```

## 4. GitHub Release

1. 在 GitHub 创建新 Release。
2. tag 与版本号一致，例如 `v0.1.7`。
3. 上传 NSIS 安装包：`AiSync_<version>_x64-setup.exe`。
4. MSI 当前只作为备用产物；如仍保留 MSI，可同时上传 `AiSync_<version>_x64_en-US.msi`，但用户下载入口优先选择 NSIS。
5. 发布后在 AiSync 设置页点击“检查更新”。

## 5. 更新检查验收

- [ ] 设置页能显示当前版本、最新版本、发布时间。
- [ ] 有新版本时显示“发现新版本”。
- [ ] 下载按钮优先指向 `*-setup.exe`。
- [ ] 如果没有安装包资产，下载按钮隐藏或退回打开发布页。
- [ ] “打开发布页”可打开 GitHub Release 页面。
- [ ] 网络失败、GitHub API 失败、打开链接失败时前台显示错误。

## 6. 发布后记录

- [ ] 更新 `CHANGELOG.md`，如果该文件已经建立。
- [ ] 更新 `规划.local.md` 中对应任务状态。
- [ ] 如发现安装/启动问题，把诊断信息和日志路径写入 issue 或本地记录。

## 7. 旧版清理说明

可删除：

- `%LOCALAPPDATA%\AiSync`：安装目录，删除后需要重新安装。
- `%LOCALAPPDATA%\com.aisync.app\logs`：日志目录。

谨慎删除：

- `%APPDATA%\com.aisync.app`：应用配置与启动诊断，可能包含 runtime venv 回退目录。

不要误删：

- 用户选择的小说项目目录。
- 项目内 `.aisync/`，其中包含对话历史、工具运行记录和向量索引。
