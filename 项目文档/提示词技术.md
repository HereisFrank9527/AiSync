# 提示词技术设计

更新时间：2026-05-20

## 目标

AiSync 的提示词系统不做“万物皆 prompt”的大杂烩。长期方向是：

- 事实类内容结构化管理
- 行为类规则提示词化管理
- 执行过程工作流化编排

这样既保留提示词可编辑、可复用、可模板化的优点，又避免人物、伏笔、大纲、世界观等项目事实散落在提示词文本里。

## 核心分层

### 1. Prompt Pack

Prompt Pack 只管理模型行为规则。

适合放入 Prompt Pack 的内容：

- 文风规则
- 写作习惯
- 润色标准
- 输出格式
- 禁忌与偏好
- 特殊模型片段规则
- 检查/评审口径

不适合放入 Prompt Pack 的内容：

- 人物档案
- 伏笔状态
- 大纲节点
- 世界观事实
- 章节正文
- 时间线事实

这些属于项目对象，应继续由对象工作台和项目文件管理。

### 2. Context Pack

Context Pack 管理“本次任务需要注入哪些结构化上下文”。

Context Pack 不要求用户手写大量提示词，而是从项目对象中自动抽取内容，例如：

- 本章相关人物
- 本章相关伏笔
- 当前大纲节点
- 相关世界观规则
- 最近章节摘要
- 相关历史设定
- 检索命中的项目片段

Context Pack 的价值是让 Agent 知道“该看哪些对象”，而不是把所有事实长期复制进 prompt。

### 3. Workflow Step

Workflow Step 管理“什么时候用什么提示词、上下文和模型”。

一个步骤应能声明：

- 使用哪个 LLM 预设
- 使用哪些 Prompt Pack
- 使用哪些 Context Pack
- 输入来自哪里
- 输出写到哪里
- 是否需要人工确认
- 失败后是否可重试/跳过/编辑提示词

示例：

```text
步骤：章节草稿
模型：默认写作模型
Prompt Pack：主线文风、章节草稿规则
Context Pack：当前大纲节点、本章人物、相关伏笔、世界观规则
输出：temp/drafts
确认：需要
```

```text
步骤：特殊片段
模型：Grok 预设
Prompt Pack：特殊片段规则
Context Pack：当前场景上下文
输出：temp/drafts
确认：需要
```

## 为什么不采用“所有提示词集中一锅管理”

参考项目里常见的做法是把人物、伏笔、剧情、大纲、文风等内容都放进同一个提示词管理器，并用模板语法组织。

AiSync 不直接照搬，原因是：

- 人物、伏笔、大纲、世界观是项目事实，应该可统计、可筛选、可关联、可检索。
- 事实写进提示词后容易与正式对象数据重复，长期会产生不一致。
- Agent 很难区分“事实设定”“写作偏好”“临时指令”。
- 后续章节工作流、伏笔提醒、关系图、向量检索都依赖结构化对象。

因此 AiSync 只吸收该方案的优点：

- 集中管理
- 模板语法
- 可启用/停用
- 可复用
- 可按阶段选择

但不接受“万物皆 prompt”。

## 数据边界

```text
人物 / 伏笔 / 世界观 / 大纲 / 章节
  = 项目对象与结构化数据

文风 / 规则 / 偏好 / 输出格式 / 特殊模型要求
  = Prompt Pack

本轮需要哪些项目对象
  = Context Pack

执行顺序、模型选择、确认点、输出位置
  = Workflow Step
```

## 模板语法方向

Prompt Pack 后续可以支持轻量模板变量，例如：

```text
请保持《{{project.name}}》的主文风。

本章目标：
{{chapter.goal}}

相关伏笔：
{{foreshadows.related}}

请避免：
{{rules.forbidden}}
```

模板变量应由 Context Pack 或 Workflow Step 提供，不鼓励用户手动维护重复事实。

## 当前实现状态

截至 2026-05-20：

- 已有全局 Prompt Pack 存储：`~/.aisync/prompt_packs.json`
- 已有 `/api/prompt-packs` CRUD
- 设置页已有“提示词管理”基础页面
- 已启用且适用阶段包含 `chat` 的 Prompt Pack 会自动注入主 Agent 对话
- AgentRun 的 `prompt_audit` 会记录本轮使用的 Prompt Pack 数量和名称
- `write_chapter` AI 生成会自动注入适用阶段包含 `chapter_draft` 的 Prompt Pack
- `edit_chapter` AI 生成会自动注入适用阶段包含 `revision` 的 Prompt Pack
- ToolRun 的 `result.metadata.prompt_packs` 会记录本次工具生成使用的提示词包阶段、数量和名称
- 每个项目可在 `.aisync/prompt_pack_settings.json` 保存提示词使用方式：默认沿用全局启用；切到项目模式后，只使用本项目勾选的 Prompt Pack
- 已有 WorkflowRun/WorkflowStep 持久化骨架：项目内 `.aisync/workflows/{run_id}.json`，前端“工作流”页可创建章节草稿流程模板并查看步骤状态
- 章节草稿工作流已有最小执行器：手动点击“运行下一步”可执行上下文检索、章节计划、用户确认暂停、草稿生成，并把草稿写入 `temp/drafts/{run_id}.md`
- Context Pack 尚未实现
- Workflow Step 执行器仍是最小版；尚未支持自动连续执行、步骤编辑、分段长文、diff 确认和正式章节写入

## 下一步

优先级建议：

1. 工作流步骤编辑：用户确认前可修改计划/提示词/输出目标，再继续执行。
2. 定义 Context Pack 数据结构，先覆盖“本章人物、相关伏笔、当前大纲节点、相关世界观”。
3. 分段长文写作：把 draft 步骤拆成多个场景/段落，降低长输出失败率。
4. 正式写入确认：草稿先在 `temp/drafts`，用户确认后再写入 `chapters/**.md`。
